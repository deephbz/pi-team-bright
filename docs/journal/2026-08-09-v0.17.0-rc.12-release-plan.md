## Intended change

Port the accepted DAG-native Task contract onto the semantic-hardened rc.11
subsystem boundaries. Keep nine leader tools. `task_create` atomically creates
one keyed Task DAG and owns later graph expansion. Remove `task_link` from the
normal leader surface.

Map many Tasks to fewer stable Workers while one Task keeps one owner. Task
authority selects at most one ready Task for each free Worker. Dependency
advancement must not require a leader model turn.

## Release guards

The final source must prove:

- atomic graph creation and exact operation replay through real Beads;
- graph-only commit recovery without duplicate Tasks or successful-replay
  events;
- ready-only initial delivery, blocker-aware claim, mechanical successors,
  parallel Workers, one slot per Worker, and blocked-slot release;
- injected Task publication, graph orchestration, and ready-delivery boundaries;
- unchanged `caught_up` and `indeterminate` observation semantics;
- raw, model, collapsed TUI, expanded TUI, and role-specific tool parity;
- fast and exhaustive test-lane closure on the exact final tree;
- package build, clean packed-artifact installation, and extension load;
- a live Pi multi-Session canary with an assigned Task and Worker-authored Task
  event as launch evidence; and
- public-content, persistence, link, JSON, Git identity, and privacy checks.

Run focused tests while the tree changes. Run the broad package aggregate once
after the final source bundle is stable. If it fails, isolate and repair only
the failing class before one final aggregate rerun.
