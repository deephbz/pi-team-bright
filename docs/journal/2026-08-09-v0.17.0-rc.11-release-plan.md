# v0.17.0-rc.11 release plan

Date: 2026-08-09
Stage: sharing
Architecture impact: changed internally for Task and Team dependency ownership;
public behavior and HyperCarrier's opaque internal view are unchanged

## Purpose

Prepare the source candidate that carries the semantic-hardening series after
published `0.17.0-rc.10`. The candidate makes Task reconciliation and mutation
publication dependencies explicit, moves durable lead-Session discovery into
Team authority, and adds characterization and measurement evidence. It does not
change public tools, schemas, package exports, persisted records, filenames,
retry, timing, or default behavior.

## Source preparation

Set package and lock metadata, README installation text, image provenance URL,
release parity metadata, maintained context, and Project result evidence to
`0.17.0-rc.11`. Keep exact Task-publication contracts in source and tests;
release documents point to those anchors instead of copying their definitions.

This plan records source preparation only. It creates no tag, push, npm
publication, GitHub release, or final verification claim. Published npm `next`
remains `0.17.0-rc.10` until a later authorized release operation succeeds.

## Required order

1. Commit the exact rc.11 source candidate, including the result bundle and
   release metadata.
2. Run the one reserved full aggregate lane once on that exact committed source.
3. If the aggregate passes, run the remaining release verification and record
   exact evidence before any publication decision.

Do not run the aggregate before the source-candidate commit. A pre-commit
aggregate would test a different source identity and would not satisfy the
release gate.

## Source-preparation checks

The uncommitted candidate must pass version and lock consistency, JSON parsing,
Markdown-link checks, diff checks, typecheck, and packed-package verification.
These checks establish source readiness only. They do not replace the
post-commit aggregate or prove publication readiness.

## Deferred release operations

Tagging, pushing, npm publishing, npm `next` changes, registry and provenance
verification, GitHub prerelease creation, and a final release receipt remain
separate authorized work after the exact committed candidate passes its reserved
aggregate and release gates.
