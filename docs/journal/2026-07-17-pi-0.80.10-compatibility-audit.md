# Pi 0.80.10 compatibility audit

Date: 2026-07-17

Status: completed compatibility record

## Trigger

Pi 0.80.8 changed the model/auth runtime and PiTeams constructs Pi's exported
`FooterComponent` for its Team identity projection. The next two Pi releases
landed on the same day, so the extension surface needed to be checked through
0.80.10 rather than against the first breaking release alone.

## Upstream evidence

- [Pi 0.80.8](https://github.com/earendil-works/pi/releases/tag/v0.80.8)
  replaced SDK `authStorage` and `modelRegistry` options with `modelRuntime`,
  made `ModelRegistry.refresh()` asynchronous, and moved authentication and
  catalog behavior behind the runtime projection.
- [Pi 0.80.9](https://github.com/earendil-works/pi/releases/tag/v0.80.9)
  added Kimi K3 support and deferred tool loading; it did not remove a PiTeams
  extension API.
- [Pi 0.80.10](https://github.com/earendil-works/pi/releases/tag/v0.80.10)
  repaired Kimi compatibility and the xAI catalog; it did not add another
  relevant extension-surface break.

## Impact assessment

The custom footer was the only confirmed PiTeams incompatibility. Pi's default
footer now asks `AgentSession.modelRuntime` whether the active provider uses
OAuth, while the PiTeams footer adapter supplied only the older
`modelRegistry` projection. Rendering therefore failed at runtime even though
the extension-facing `ExtensionContext.modelRegistry` API remained available.

PiTeams does not construct sessions through the changed SDK options, refresh a
model registry, register providers, or rely on deferred tool activation. Its
tool definitions, extension events, tool renderers, TUI text primitives, and
session-entry reads remain compatible with 0.80.10.

## Change and verification

The package baseline is now 0.80.10. The footer adapter supplies the current
`modelRuntime.isUsingOAuth(provider)` projection, teammate role text is dimmed
while `team-lead` retains the accent color, and the identity prefix includes
the local `HH:MM` time of the latest Session message when one exists.

`npm test` passed with 45 test files and 357 tests. The subprocess-heavy Beads
surface scenario passed alone in 114 seconds but exceeded its former 180-second
budget under full-suite contention, so only that file's test budget was aligned
with the existing 300-second headless QA integration budget.
