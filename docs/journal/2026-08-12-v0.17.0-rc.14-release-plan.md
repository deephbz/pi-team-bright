## Authorized publication sequence

The owner authorized the complete rc.14 release operation. Do not request a
second midstream authorization. Use the exact release commit after all local
gates pass, and stop on any mismatch.

1. Push the committed candidate without a tag.
2. Dispatch `.github/workflows/publish.yml` with `dry_run=true`, a unique
   `run_nonce`, and `tag=next`. Confirm that its tested commit equals the
   candidate commit.
3. Create annotated tag `v0.17.0-rc.14` at that same commit. Push the tag only
   after the dry run passes.
4. Dispatch the workflow again with `dry_run=false`, a new `run_nonce`, and
   `tag=next`. The workflow runs `test:full`, `test:lanes`, and
   `verify:package` before `npm publish --access public --provenance --tag next`.
5. Query npm for version, `next` dist-tag, integrity, and provenance. Download
   the published tarball and compare it with the recorded pack artifact.
6. Create the GitHub prerelease from the annotated tag. Use the approved public
   identity only.
7. Append a receipt with the exact commit, tag object, workflow runs, gate
   outcomes, package integrity, provenance result, registry result, release URL,
   and privacy result.

Stop on any mismatch or failed gate. Do not publish, retag, or make a release
claim from a draft, local plan, or dry run.

## Proof limits

Local gates prove deterministic repository and package behavior. They do not
prove real Pi process behavior, Beads/Dolt contention, external writers,
watcher delivery, OS scheduling, terminal rendering, registry state,
provenance, or publication before their separate recorded checks.
