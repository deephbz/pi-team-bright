## Proposed prerelease text

`@hypercarrier/pi-team-bright@0.17.0-rc.14` fixes two production lifecycle
failures without changing the public coordination contract.

`team_sync` no longer joins runtime writer locks. It ignores unavailable macOS
watch filenames, coalesces watcher scans, and joins one complete Task-authority
projection per Team. This prevents filesystem feedback storms and overlapping
Beads list reads when an outer wait times out or is cancelled.

Worker recovery now holds the exact Membership lease through revalidation,
preflight, spawn, and target persistence. The replacement child alone claims
runtime startup, and its expected Membership identity rejects stale children.
This prevents the leader from rejecting and stopping a valid fast replacement.

The isolated macOS E2E used a Sol-high leader and eight Terra-medium Workers.
All nine Tasks closed with Worker evidence, safe recovery passed, all Workers
stopped, and Team shutdown retained no unfinished Tasks. The external monitor
matched 27 `team_sync` calls. Product-call duration was 16 to 5,308 ms, no calls
overlapped, and at most one descendant Beads list process was live. Seventy-four
one-second samples each had three FSEvent string occurrences, not the thousands
seen during the incident.

One Task creation returned an unknown timeout and succeeded through the required
exact-operation retry. This is existing Task-authority contention behavior, not
a regression or part of this repair.
