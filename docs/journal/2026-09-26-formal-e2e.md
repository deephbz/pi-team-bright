# Public-tool recovery evidence

The hardening check loads the actual extension in fresh Node processes. It
registers public tools against an isolated Team and invokes those tools through
their registered `execute` functions. The fixture has a private `HOME`; it does
not open a Pi provider session or a terminal pane.

The test kills the first process after `task_graph_apply` commits a two-Task
graph. A second process replays the same operation, reads both Tasks, and
acknowledges a `team_sync` snapshot through the extension's persisted-result
hook. The graph snapshot and Team event journal stay byte-identical on replay.
Worker processes claim and achieve the prerequisite Task. An incomplete graph
read then makes `team_sync` unavailable. After the graph file is restored, a
fresh leader process receives updates from the earlier acknowledged position.
The dependent Task becomes ready. Its claim records the prerequisite's accepted
Attempt ID. A stale Worker version cannot repeat the outcome. The test reads
the durable graph snapshot and Task event journal as external anchors.

`src/utils/formal-hardening-public-recovery.test.ts` passed on supported Node
22.22.1. `npm run typecheck --workspaces=false` passed. The public recovery
test is deterministic integration evidence. It does not test a live Pi model,
provider, carrier, or Team launch. It does not prove every crash window.

The test audit removed four duplicate source-text assertions from

construction assertions remain in the alert-port and Task-publication tests.
The owning model-tool test still checks its distinct composition and import
