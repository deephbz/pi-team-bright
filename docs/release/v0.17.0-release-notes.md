# Pi Team Bright v0.17.0

Pi Team Bright `0.17.0` adds deterministic mission graphs, explicit Task
outcomes, a read-only graph pane, and faster Worker startup paths. It keeps the
Task plus its assignee as the only executable work contract.

## Highlights

### Apply a complete mission graph

The new `task_graph_apply` leader tool atomically applies one complete assigned
Task graph. It supports:

- success-only `needs` edges;
- parallel ready fronts across stable Workers;
- one active execution slot per Worker;
- success joins that bind accepted Attempt lineage;
- explicit, bounded `on_goal_failed` repair edges;
- exact graph-version checks for later revisions;
- operation replay without duplicate Tasks or Attempts.

A Task now distinguishes `dependency_waiting`, `ready`, `in_progress`,
`blocked`, `goal_failed`, `goal_achieved`, and `cancelled`. Only
`goal_achieved` satisfies a prerequisite.

Every claim starts an immutable Attempt. The Attempt records its input lineage,
resolved model alias, and outcome evidence. A failed criterion can return to
specified repair work, but Task authority stops the route at its declared
traversal limit.

### Inspect the graph without changing it

In Herdr, `/pi-team-graph` toggles a read-only Task graph pane in the current
exact tab. The pane provides:

- top-to-bottom and left-to-right layouts;
- clear fork, join, success, and repair routes;
- deterministic packing for disconnected islands;
- pan, selection, spatial navigation, and bounded Task details;
- terminal-owned semantic colors for automatic light and dark themes;
- bounded views for large graphs, with visible omissions and freshness.

The pane reads Task authority. It never schedules or changes work.

### Keep human messages concise and consistent

Tool calls, results, lifecycle events, Task delivery, Alerts, and sync nudges
now use one TUI projection. Collapsed messages show the decision-relevant
summary. Expanded messages retain structured details for investigation.

### Reduce avoidable Worker startup work

Worker default-model validation now uses Pi's invocation-local model registry
instead of starting another Pi CLI. Measured p95 fell from 4,464 ms to less
than 1 ms for this stage.

A Herdr version with accepted-start support can reduce its actuation wait from
about 3,059 ms p95 to about 65 ms p95. Older Herdr versions keep the safe legacy
wait. Exact Membership, Session, process-generation, and runtime checks still
define Worker admission.

Reusing an already bound Worker remains the fastest supported path. The live
canary measured 33 ms p95. A fresh Pi process still has an observed floor near
461 ms before exact Worker binding.

## Breaking model-tool changes

This release changes the model-facing Task contract:

- `task_graph_apply` replaces `task_create`.
- Request-local `needs` keys replace separate model-authored link operations.
- `task_update` applies one explicit transition with an exact Task version.
- `goal_achieved` and `goal_failed` replace ambiguous closure semantics.
- `dependency_waiting` and `ready` are derived and cannot be authored.

Update saved prompts, extensions, or scripts that call the prior tools. The
leader surface remains nine tools, and the Worker surface remains the three
Task/Alert tools needed for assigned work.

## Upgrade and existing Teams

Install the stable version, then restart each Pi process that must load it:

```sh
pi install npm:@hypercarrier/pi-team-bright@0.17.0
```

Do not recreate a Team only because the package version changed. Before the
first graph apply, existing legacy Tasks continue through the Beads-backed
compatibility path. A legacy `closed` Task does not become `goal_achieved`
without durable success evidence.

The package owns `@beads/bd@1.1.0`; a separate global `bd` installation is not
required. Pi `0.83` or later is required for exact Worker run-state evidence.

## Important limits

- The graph pane requires Herdr and is read-only.
- Model aliases are recorded per Attempt. Changing an alias does not promise to
  switch an already-running Worker process.
- Ordinary `team_sync` can still report Task-authority unavailability during
  Beads list contention. Preserve the last valid cursor and retry.
- Large graph views are bounded projections, not a public Task-count service
  level objective.
- Team state is local machine state. Pi packages and Workers run with the full
  access of the current user.

## Verification basis

The stable release source passed 142 test files and 1,007 tests; 8 files and
16 causal variants were intentionally skipped. Package installation,
generated-output, lane-closure, TUI sentinel, and model-surface gates passed.

A fresh exact-source multi-Session Team exercised all nine leader tools and all
three Worker tools. Six Tasks reached `goal_achieved`, including a bounded
failure repair and an exact accepted-lineage join. Both Workers stopped and
shutdown retained no unfinished Tasks. An earlier stress run closed 117 of 117
Tasks across eight Workers.

The final release operation records main CI, package integrity, registry,
provenance, and GitHub Release evidence separately.
