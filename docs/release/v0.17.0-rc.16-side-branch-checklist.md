## Product and safety boundaries

- Task authority owns graph revisions, Attempts, readiness, bounded failure
  traversal, replay, and recovery.
- Exact current Membership, Pi Session, PID, and runtime generation own Worker
  admission. Herdr actuation acceptance is not Worker readiness.
- Startup optimization does not change tool names, parameters, result kinds,
  Task claims, or public Worker meaning.
- Worker defaults use Pi's invocation-local model registry. The snapshot is not
  persisted.
- Ready delivery remains outside `ensure_worker`. Session start, Task
  transitions, and periodic recovery own it.
- The read-only graph pane and both galleries are projections. They never
  mutate Task authority.
- The graph pane pins the package TypeScript project from another cwd.
- Graph status colors use semantic ANSI slots. The terminal palette controls
  light and dark appearance.
- Stable bound-Worker reuse is the supported low-latency path. Generic warm
  pools and production compile caching remain rejected.
- [Decision 0012](../decisions/0012-worker-startup-latency.md) preserves the
  startup decision, evidence, costs, consequences, and reversal criteria.
