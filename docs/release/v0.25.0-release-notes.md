# Pi Team Bright 0.25.0

This is the stable release on npm `latest`. It replaces 0.23.1. It contains
the 0.24.0 prerelease line (rc.1 to rc.7), which never had a final release,
plus Alert interrupt and one Herdr placement fix. The 0.24.0-rc release notes
in `docs/release/` give the detail of each change.

## Upgrade from 0.23.1

1. Read "Graph-only Task authority (0.25.0)" and "Carrier-liveness upgrade
   (0.25.0)" in the README.
2. A Team that keeps its Tasks in Beads and has no graph cannot run under
   0.25.0. Finish it with 0.23.1, or keep its store and start a new Team.
   PTB never deletes, exports or migrates `.beads/` data.
3. On macOS, the `postinstall` hook builds the process-generation helper when
   `rustc` is available. Without it, installation succeeds and PTB warns once
   at Pi startup with the build command.
4. Install the exact version. `/reload` alone keeps the pinned old version.

   ```sh
   pi install npm:@hypercarrier/pi-team-bright@0.25.0
   ```

5. Reload the lead's Pi first, then reload each Worker's Pi.

## Upgrade from 0.24.0-rc.7

Install 0.25.0 as above, then reload the lead's Pi first and each Worker's Pi
after it. No data migration is necessary. Existing Alert records read as
non-interrupting.

## Alert interrupt

`alert_send` takes an optional lead-only `interrupt` flag. It defaults to
false. When it is true, delivery aborts the recipient's in-flight Pi
operation, waits up to 10 s for it to settle, and then presents the Alert as a
steer, so it starts a new turn at once. An idle recipient is not aborted.
Workers cannot set the flag, and the sender refuses it from anyone except
`team-lead`. Alerts still never change Task state.

## Changes since 0.23.1

- **Team cursor on the lead's branch.** `ptb.team-update` entries and
  `team_sync` results live on the lead's Session branch. Compaction, fork and
  tree navigation keep them.
- **Worker liveness from the process generation.** PTB identifies a Worker
  process by PID, birth token and boot ID. Elapsed time never closes a pane. A
  durable launch ID fences each launch, and a stalled launch asks the human
  instead of spawning again.
- **Graph-only Task authority.** The Task graph snapshot is the only Task
  authority. Every graph mutation holds the exact-Membership lease.
- **Received Alerts after compaction.** The `team_sync` snapshot recovers
  recent received Alerts.
- **Delivery isolation.** One recipient's delivery failure or retry does not
  block other recipients.
- **Lead responsiveness.** Graph reads, journal reads and durable writes are
  incremental or asynchronous. A long-lived lead Session no longer freezes
  its pane during `team_sync`.
- **Membership state machine.** Every Worker lifecycle write goes through one
  total state machine. A refused spawn writes nothing, and `worker_stop` can
  stop leftover launch records.
- **Task observation.** `@hypercarrier/pi-team-bright/observation` exports
  `readTaskSnapshot`, a read-only `pi-team-tasks/1` snapshot for viewers.
- **Herdr placement.** A Worker pane that is too narrow for a side-by-side
  split now tries a downward split.

## Known limits

- No test covers a Team with mixed versions. Reload the lead first to keep
  that period short.
- An interrupt aborts the recipient's current run, including a turn that a
  person started in that Worker's pane.
- Linux: probes A7 and A9 and a 4-lead x 25-Worker run passed on one host.
  Larger scale and a full Linux Team with real Pi and Herdr have not run.
- A lost-graph message names no restore procedure.
- On a cold jiti transform cache, PTB adds about 2.5 s of startup CPU. Keep
  `TMPDIR` stable so that the cache stays warm.
- Long operations show no progress and cannot be cancelled.
