# Pi Team Bright v0.22.0

## Every leader team_sync result is actionable

Previously, every second consecutive leader `team_sync` call returned
`indeterminate` and wasted a model turn. Pi runs an assistant message's tool
calls before `turn_end`, but Pi Team Bright acknowledged the earlier result
only at `turn_end`. The result is now resolved at the assistant `message_end`,
before that message's tools run. If the presentation proof is absent or the
acknowledgement fails, the result is discarded and the next call re-reads
from the committed baseline.

Other results that carried no actionable information change too:

- A second `team_sync` call in one assistant message returns `refused` with
  reason `observation_in_progress`.
- When nothing changed but a Worker is not proven settled, `team_sync` returns
  the new kind `unsettled`. It names each Worker and the missing evidence.
  `caught_up` keeps its meaning.
- `updates` without a baseline returns the snapshot directly.
- Updates skip pages with no visible change.

`indeterminate` is no longer a model-visible result. Old Session entries that
contain it still render and replay.

## Pi-tui 0.84 and later

The Task graph pane and the review galleries now construct the main screen on
pi-tui 0.84 and later, including Pi 1.0.0. Earlier code exited with an error
on pi-tui 1.0.0.

## Verification layers

The repository adds a TLA+ model of the leader sync turn, a state traversal
of the observation service, and scripted real-Pi scenarios.
`docs/maintainers/scenario-verification.md` explains how to add a scenario.

## Upgrade

Install `pi install npm:@hypercarrier/pi-team-bright@0.22.0`, then restart Pi.
No Team storage migration is required. Pi `>=0.83.0` remains required. Prompts
or tooling that match on `indeterminate` should handle `unsettled` and
`refused` instead.
