# Pi Team Bright 0.24.0-rc.3

This is a prerelease on npm `next`. It makes the Task graph the only Task
authority and removes Beads, Dolt and the TLA+ models (Decision 0024). It also
recovers received Alerts after compaction (Decision 0023) and isolates delivery
failures that the Linux real-scale run found. Install it by exact version:

```sh
pi install npm:@hypercarrier/pi-team-bright@0.24.0-rc.3
```

For a live Team, reload the lead's Pi first, then reload each Worker's Pi.

## Graph-only Task authority (Decision 0024)

`team_create` writes an explicit empty graph snapshot before it succeeds. It
creates no Beads workspace. Every Task read, transition, guard, view and
delivery path uses the graph. Worker startup never runs `bd`, so a Dolt lock
can no longer stop a Worker's delivery. A Team with a graph and old Beads fields
uses the graph and ignores those fields. A missing or corrupt graph is
unavailable. It is never an empty Task list.

The package no longer depends on `@beads/bd` and its embedded Dolt. The legacy
Task migration commands and the binary setup scripts are gone.

## Beads Teams are not supported

A Team that keeps its Tasks in Beads and has no graph cannot run under 0.24:

- Task operations fail closed with this message: "This Team keeps its Tasks in
  Beads. PTB 0.24 does not support it. The data stays in .beads/."
- `worker_stop` and `team_shutdown` return `unavailable` with reason
  `team_authority_unavailable`. They do not throw.
- Task delivery stops once with no automatic retry. Alert delivery continues.
  The toast and the `/ptb status` detail say: "Finish this Team with its
  original PTB version or start a new Team."
- `/ptb status` names the unsupported Beads store. It shows no graph path.
- PTB never deletes, exports or migrates `.beads/` data. The data stays on disk
  and remains readable with an external `bd` binary.

A Team with a `task-authority/` directory or a `graph-revision-retirement.json`
fence and no graph snapshot has lost its graph. PTB reports that the graph
authority needs restoration, even if the Team also has Beads fields.

## Safety fixes in the graph path

- Every graph mutation holds the exact-Membership lease and rechecks the
  Session. This covers Worker `task_update`, leader `task_update` and
  `task_graph_apply`. A replaced or stopped Worker gets a refused result with
  `state_changed: false`.
- Task delivery requires graph authority. If the graph disappears during a live
  scan, nothing is presented and the error goes to the delivery failure path.
- A recovery record from before 0.24 that has no target persists its selected
  target before it is enqueued. A replay after a failure and a Worker
  replacement reuses that target, so the record makes one delivery only.

## Received Alerts after compaction (Decision 0023)

The `team_sync` snapshot result gains `alerts` and `alerts_omitted`. `alerts`
lists the newest 10 Alerts that the caller's current Membership received. Each
text is a preview of at most 2000 code points. The read never marks an Alert
read, starts a delivery or changes a Task. If the Alert history is unavailable,
the snapshot says so.

## Delivery isolation

- Alert delivery and Task delivery start and fail independently. A Task
  delivery failure never stops Alert delivery, and the reverse. A failed start
  retries with a bounded backoff while the binding stays current. `team_sync`
  and `/ptb status` show the degraded state.
- Carrier advice for an idle Worker that holds an `in_progress` Task tells the
  lead to inspect that Task and decide. It does not say wait. Idle alone never
  authorizes a spawn or a replacement.
- An `alert_send` receipt says that `accepted` means stored for the recipient.
  It does not mean presented or processed. If the recipient's delivery is
  degraded, the receipt says so.

## TLA+ models removed

The `formal/` TLA+ models and their CI job are gone. They were stale. The
deterministic simulator and its exhaustive campaign replace them. The full
exhaustive lane (`npm run test:exhaustive-only`) takes about 12 minutes.

## Known limits

- `npm run probe:model-tools` fails before it runs with
  `ERR_PACKAGE_PATH_NOT_EXPORTED` for `@earendil-works/pi-ai` under the ts-node
  loader. The failure predates this release. Registered-tool tests remain the
  interface evidence.
- Linux: probes A7 and A9 and a 4-lead x 25-Worker real-scale run passed on one
  host. Larger scale, a host crash, a shared Herdr outage and Worker replacement
  at scale have not been tested.
- A lost-graph message names no restore procedure.
- Worker progress recording depends on Worker instructions. Nothing enforces it.
