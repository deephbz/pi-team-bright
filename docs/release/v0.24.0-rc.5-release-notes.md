# Pi Team Bright 0.24.0-rc.5

This prerelease was published to npm `next` by mistake. Use 0.24.0-rc.6
instead: it contains these changes and the lead-pane freeze fix. See
`v0.24.0-rc.6-release-notes.md`. This release hardens Worker Membership. Failed
spawns now report their real cause and leave no stuck records. Leftover launch
records can be stopped without a terminal kill. Tasks, Alerts and the on-disk
formats do not change.

## Membership state machine

One total state machine in `src/team-authority/membership-machine.ts` is now
the only writer of Member lifecycle fields. It parses every persisted Member
shape, and it either applies, keeps or refuses each lifecycle event with a
named reason. The direct field writers and generic lifecycle patches are gone.
The project report is `docs/projects/state-machines/report.md`.

## Visible behavior changes

- **Spawn refusal:** a spawn that fails before it reaches the terminal (for
  example, no room for a pane) reports a refusal with its cause. It no longer
  reports `created`, and it adds no Member.
- **Terminal failure after the request:** a launch that the terminal refuses
  records `refused` with the terminal's fact. Later spawns no longer blame
  another Worker's leftover record.
- **Stop:** `worker_stop` on a leftover launch record (`requested`, `unknown`
  or `refused`) now succeeds when no process can exist, with no terminal
  kill. A stop with no proof of `process_stopped`, `no_process_possible` or
  `session_left` is refused as `process_may_exist`.
- **Retry:** an expired Herdr launch that never started retries automatically
  (`first_binding_retry`) on the next `ensure_worker`. A launch that can still
  bind gives `attention` with `launch_pending` and `wait`. The skill documents
  both.

## Evidence

- The simulator replays the live wedge of 2026-10-16. rc.4 leaves 3 records
  that no tool can stop. rc.5 reports both refusals with their geometry cause
  and leaves no records.
- The seven live wedge records replay to 1 recovered launch and 6 stops, with
  0 terminal kills.
- The exhaustive explorer covers 3,154 states. Two-stage states that only a
  human can clear drop from 45 to 1. The remaining state is a pre-rc.1 record
  without a launch fence, and the machine refuses its stop.
- 44 simulator runs (202 Membership changes) conform to the machine with 0
  violations.
- `npm test` takes 74-75 s against 60-66 s for rc.4 under equal load. The
  added 9 s simulator wedge replay causes most of the difference. Task
  hydration latency is unchanged.

## Known limits

- If a Herdr split succeeds but the target write then fails, the pane has no
  Membership record.
- Attention reasons are still free strings. The pane-placement refusal does not
  name an operator action.
- The machine trusts the shell's `refused` and stop-authority evidence.
- No tool repairs an `invalid` Membership record.
- In the tool-result QA suite, the final full Team shutdown throws in the
  harness, because the harness never sends `session_start`. Production always
  sends it.
- The lead-pane freeze in long-lived lead Sessions is not fixed in this
  release.
